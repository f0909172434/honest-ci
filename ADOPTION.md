## Evidence rules

A public integration entry needs a link to a repository outside the
maintainer's own account that visibly pins or installs HonestCI. Record only the
minimum facts needed to reproduce the compatibility claim. A public issue,
pull request, or release link is required before recording feedback as having
changed the project.

Do not infer adoption from stars, forks, npm downloads, GitHub clone traffic,
or screenshots. Those signals can include bots, CI, mirrors, the maintainer's
own validation, and repeated activity from the same user. Private usage is
recorded only as an aggregate count when the user explicitly opts in and
provides reproducible, sanitized evidence; never list a private repository.

## Add or correct an entry

Open a [compatibility report](https://github.com/f0909172434/honest-ci/issues/new?template=compatibility.yml)
or a focused pull request. Include the public evidence URL and whether you want
the repository named here. Anyone listed may ask to have the entry removed.

Recheck links before each release and at least monthly while a launch campaign
is active. Remove or annotate evidence that no longer resolves; do not preserve
an adoption claim only because it once appeared true.
